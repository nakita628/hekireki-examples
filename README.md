## Notes

- Each schema is imported at the commit pinned in [sources.json](./schemas/sources.json) by [import-schema.mjs](./tools/import/import-schema.mjs). The project's own generator blocks and connection URLs are dropped, and hekireki's generator blocks are added. Everything else is kept as the project wrote it.
- A multi-file schema (`prismaSchemaFolder`: rallly, dub, papermark, formbricks) is joined into one file in path order.
- The `views` preview feature is carried over where the schema has views (calcom, langfuse).
- `hekireki-exposed` writes PostgreSQL only, so it is left out of taxonomy, dub (MySQL), nextauth and anythingllm (SQLite).
- `hekireki-eloquent` is left out of formbricks: a relation field named `refresh` collides with Eloquent's `Model::refresh()`, and the generator refuses it.
- The ER diagram is also written as [DBML](./schemas/calcom/generated/er/er.dbml) and [SVG](./schemas/calcom/generated/er/er.svg).

## Usage

[Bazel](https://bazel.build/) through [bazelisk](https://github.com/bazelbuild/bazelisk). The npm packages come from `pnpm-lock.yaml` through rules_js.

```sh
# Generate every schema and compare with the committed generated/
bazel test //...

# Regenerate one schema into generated/
bazel run //schemas/calcom:generate.write

# Re-import every schema at its pinned commit
node tools/import/import-schema.mjs --all
```

The generated code is compiled by each ORM's own toolchain on CI ([lang-check.yml](./.github/workflows/lang-check.yml)): tsc for drizzle and kysely, go vet for GORM, cargo check for SeaORM, mypy --strict for SQLAlchemy and Django, mix compile for Ecto, Active Record and Eloquent loading every model, dotnet build for EF Core, and Gradle for Exposed.

To add a schema, add it to [sources.json](./schemas/sources.json) and [schemas.bzl](./schemas/schemas.bzl), run the import script with its name, copy a `BUILD.bazel` from another schema, and run its `generate.write` target.
